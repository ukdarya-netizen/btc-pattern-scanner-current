# BTC Bullet — BTC signal bot

Сигнальный бот только по BTC-USDT (BingX perpetual), лонги и шорты, по образцу AltBullet: цикл сканирования на закрытых свечах, журнал всех решений паттернов с метриками, виртуальное сопровождение каждой сделки, статистика и Telegram-канал. Автоторговли нет — сигналы для ручной торговли.

## Типы сделок (`artifacts/api-server/src/config/profiles.ts`) — с 2026-10-25
Только два таймфрейма, 1h и ниже убраны по решению владельца.
| Тип | Плечо | ТФ | Макс. удержание |
|---|---|---|---|
| h4 (4 часа) | x20 | 4h | 10 дней |
| d1 (1 день) | x10 | 1d | 45 дней |

Стоп и цели берутся из диапазона (см. ниже). Стоп обязан быть не дальше 80% расстояния до ликвидации (x20 → ≤ ~3,7%, x10 → ≤ ~7,7%); иначе сигнал не открывается. После первой цели стоп в безубыток.

## Сигналы: Auto Range Detector [QuantAlgo] (`engine/rangeDetector.ts`, `engine/rangePatterns.ts`)
Порт индикатора 1:1 с его настройками по умолчанию, только по закрытию бара. 8 сетапов: {4h, 1D} × {пробой, девиация} × {лонг, шорт}.
- Пробой: подтверждённый диапазон закрылся за границей + 0,15 ATR. Вход по направлению пробоя. Стоп — середина диапазона. Цели: граница ± 1× и ± 2× высоты диапазона (50/50).
- Девиация: пробой вернулся в диапазон в течение 10 баров (ложный пробой). Вход обратно в диапазон. Стоп — за снятым экстремумом + 0,15 ATR. Цели: середина, затем противоположная граница (50/50).
- Подтверждение объёмом и потоком по направлению: объём бара ≥ 1,5× (пробой) / 1,2× (девиация) от среднего за 20 баров; CVD фьючерсов за окно бара (4h или 24h) по направлению; для пробоя ещё и CVD спота. Нет данных — нет сигнала.
- Вход по живой цене; если цена уже за стопом или за первой целью — сигнал не открывается (причина в журнале решений).
- Проверка на истории (только чтение): `node --import tsx src/analysis/rangeBacktest.ts` из artifacts/api-server.

## Как работает
- `engine/runtime.ts` — запуск: восстановление открытых сделок, поток цены, цикл сканирования каждые 15 с, Telegram-очередь каждые 3 с.
- `market/bingx.ts` — свечи BingX (только закрытые), цена, WebSocket `BTC-USDT@lastPrice` с переподключением и сторожем тишины.
- `market/coinglass.ts` — агрегированные данные CoinGlass (OI, ликвидации, тейкер фьючерсов/спота, спотовый CVD, funding OI-weighted, long/short, стакан ±1%), 15m, только закрытые бары. Нет данных — метрика `null`, никаких запасных источников.
- `engine/snapshot.ts` — метрики на момент решения, набор как в AltBullet, для BTC: Δцены 5m/15m/30m/1h/3h/4h/24h; OI (все биржи) и ΔOI 15m/30m/1h/4h/24h; тейкер фьючерсов и спота (net %) 15m/30m/1h/4h; CVD фьючерсов и спота ($) 15m–24h и «CVD бычий»; объём × фьючерсов/спота (к тем же окнам за 24ч) и BingX; ликвидации лонгов/шортов 15m–24h и всплеск 1h; фандинг OI-взвешенный; Long/Short Binance и его Δ1h/4h; стакан ±1% bid/ask; Whale Index и Δ4h; ATR. Каждый 5m цикл сохраняется в `btc_market_snapshots`; метрики входа — в каждом сигнале и в сообщении Telegram.
- `engine/patterns.ts` — реестр паттернов. Пуст до утверждения паттернов по данным. `live: false` = теневой паттерн: сделки ведутся и попадают в статистику, в канал не публикуются.
- `engine/scanner.ts` — на каждой закрытой 5m свече оценивает паттерны своего ТФ, пишет каждое решение в `btc_decisions`, открывает сделку (вход = живая цена в момент сигнала). Один открытый сигнал на паттерн.
- `tracker/positionEngine.ts` — чистая логика сделки: стоп раньше целей, частичные фиксации, безубыток, тайм-аут, MFE/MAE. `tracker/tracker.ts` — применяет каждый живой тик; при разрыве потока (рестарт, переподключение, тишина >20 с) сначала проигрывает пропущенное время по закрытым 1m свечам (касание стопа и цели в одной свече = стоп).
- PnL: % цены (gross) и % к марже с плечом за вычетом тейкер-комиссий 0.05% на вход и каждый выход.
- `telegram/telegram.ts` — очередь событий (открытие, цель, закрытие), простой текст без HTML. Отдельная сохранённая доставка в канал `@bitcoinmarginmaster` и каждому подписчику; успешные доставки не повторяются при ошибках остальных получателей. До 20 доставок за проход с паузой 100 мс; не больше 8 попыток на получателя.
- `telegram/subscribers.ts` — `/start` подписывает личный чат, `/stop` отписывает; подписки и курсор `getUpdates` сохраняются в БД. Нужен единственный polling-процесс для токена; при Telegram 409 опрос останавливается с ошибкой в логе, чужие webhook не удаляются.

- `stats/reports.ts` — итоги дня, недели (пн–вс) и месяца по времени Дубая в канал, только по live-сигналам, каждый период один раз (`btc_reports`); период без закрытых сделок не публикуется.
- Дашборд `artifacts/dashboard` — состояние движка, статистика по паттернам/типам/направлениям (всё время, 30 и 7 дней), открытые позиции с текущим результатом, последние 50 закрытых. Обновляется каждые 15 с.

- `market/coinglass.ts` — как в AltBullet: регулятор запросов CoinGlass (минимальный интервал по тарифу `COINGLASS_MIN_GAP_MS`, по умолчанию 250 мс ≈ 240/мин, до 4 параллельно, при 429 — пауза до 60 с, ротация ключей), учёт сбоев API.
- `market/context.ts` — медленные источники со своим кешем: тепловая карта ликвидаций (CoinGlass model2, 3d; полосы 0–1/1–2/2–5/5–10% выше и ниже, топ-кластеры), киты Hyperliquid по BTC (позиции и открытия за 1ч), BTC на биржах (баланс и изменение 1д/7д), доминация BTC (CoinGlass, запасной CoinGecko как в AltBullet), Whale Index 4h.
- `ops/admin.ts` — уведомления админу (`TELEGRAM_ADMIN_CHAT_IDS`): «бот перезапущен»; сбой API дольше 30 мин — один раз в 6 ч, и «снова работает» только после такого алерта; сторож сканера (нет цикла 20 мин — алерт не чаще раза в час); команды `/status` и `/open` в личке бота от админа.
- `ops/lease.ts` — один движок на базу (advisory lock Postgres): второй процесс ждёт, а не дублирует сделки и сообщения.
- `analysis/candleStore.ts` — свечи BTC 1m (60 дней) и 15m (2 года) в `btc_candles`; исход каждого решения паттерна (принятого и отклонённого): что раньше — цель 1 или стоп (стоп, если оба в одной свече).
- Дашборд: вход по PIN (`DASHBOARD_PIN`, без него открыт; 10 неверных — блок 15 мин), результат по дням, исходы решений, журнал решений, контекст рынка.

## БД (`lib/db/src/schema/btc.ts`)
`btc_signals` (сделки), `btc_signal_events` (события + отметка доставки в Telegram), `btc_decisions` (все оценки паттернов с метриками), `btc_reports` (отправленные отчёты), `btc_market_snapshots` (метрики каждого 5m цикла), `btc_candles` (свечи BTC). `btc_telegram_subscribers`, `btc_telegram_state`, `btc_telegram_deliveries` — подписки, курсор и отдельные доставки.

## API
`GET /api/btc/status`, `/api/btc/metrics`, `/api/btc/stats/daily`, `/api/btc/decisions/outcomes?days=N`, `/api/btc/metrics/history?hours=N`, `/api/btc/stats?days=N`, `/api/btc/signals?status=open|closed`, `/api/btc/decisions?pattern=&decision=`.

## Секреты
`COINGLASS_API_KEY`, `TELEGRAM_BOT_TOKEN`, `DATABASE_URL`. Канал зафиксирован по указанию владельца: `@bitcoinmarginmaster`; ранее добавленный `TELEGRAM_CHANNEL_ID` сохранён, но больше не выбирает адрес назначения. Необязательно: `TELEGRAM_ADMIN_CHAT_IDS` (ID личных чатов админа через запятую), `DASHBOARD_PIN`, `COINGLASS_MIN_GAP_MS` (минимальный интервал запросов CoinGlass, по умолчанию 250 мс — тариф STANDARD), `BTC_ENGINE_ENABLED=false` (выключить движок).

## Run & Operate
- API server: `pnpm --filter @workspace/api-server run dev`
- Тесты: `pnpm --filter @workspace/api-server run test`
- Синхронизация с GitHub: workflow «GitHub Auto Sync» (`scripts/github-sync.mjs`), ветка `main`.

## Правила владельца
- Без трейлинг-стопа, без новостного фильтра, без кулдаунов — не добавлять.
- Только сигналы, реальной торговли нет.
- Все live-сигналы — и в канал `@bitcoinmarginmaster`, и в личку всем, кто подписался через `/start` в боте. `/stop` отключает личную доставку. Теневые сигналы не отправляются никуда.
- Тексты Telegram и дашборда — на русском, простой текст.
- Данные только агрегированные: нет данных — нет сигнала.
